## 2024-05-24 - [Sanitize Markdown SSR Output to Prevent XSS]
**Vulnerability:** XSS (Cross-Site Scripting) vulnerability during Server-Side Rendering (SSR). Markdown generated via `marked.parse` for project READMEs and Changelogs was directly inserted into the DOM using React's `dangerouslySetInnerHTML` without any HTML sanitization.
**Learning:** Even when fetching data from trusted sources (like GitHub API), any HTML rendered from markdown that contains raw HTML strings could execute malicious scripts if not sanitized, especially in an SSR context where the output goes directly to the client.
**Prevention:** Always use a sanitization library like `isomorphic-dompurify` in Node.js/SSR environments to sanitize any HTML output before passing it to `dangerouslySetInnerHTML`.

## 2025-04-25 - XSS Risk in SSR State Serialization
**Vulnerability:** XSS vulnerability in `frontend/server.ts` where unsanitized JSON data generated by `JSON.stringify` was directly injected into inline script tags for hydration data (`window.__SSR_DATA__`) and JSON-LD structured data. This allowed arbitrary string data containing `</script>` or other closing tags to break out of the scripts context and execute arbitrary JS code if user input is reflected in the server's state.
**Learning:** React hydration mechanisms and JSON-LD schema blocks require special care during serialization when building Express SSR wrappers, as `JSON.stringify` does not encode characters like `<`.
**Prevention:** Always escape `<` to `\u003c` via `.replace(/</g, "\\u003c")` when serializing JSON data embedded inside `<script>` tags, guaranteeing that script tags cannot be closed prematurely.
