## 2024-06-25 - Context Cancellation in Concurrent Error Handling
**Learning:** When using `context.WithCancel` to short-circuit multiple concurrent API requests (e.g., `user` and `repos`), simple sequential error checking after `wg.Wait()` can mask the true error. If `repos` fails and cancels the context, `user` may fail with `context.Canceled`. A sequential check like `if userErr != nil` will catch the `context.Canceled` first and obscure the actual root cause (e.g., a 500 or rate limit from `repos`).
**Action:** When manually managing concurrency with `sync.WaitGroup` and `context.WithCancel` without `errgroup`, check for non-cancellation errors first (e.g., `if userErr != nil && !errors.Is(userErr, context.Canceled)`) before falling back to generic error checking to ensure the true root cause is surfaced.
## 2024-08-16 - Memoizing Expensive Derived State in React Components
**Learning:** In React components like `HomePage`, expensive operations such as iterating over large arrays, filtering, sorting, and aggregating data on every render lead to unnecessary performance bottlenecks, especially when the underlying data (`data?.projects`) hasn't changed.
**Action:** Always wrap these derived calculations inside a `useMemo` hook, with the source data as the dependency array. This ensures the calculations run only when the source data actually updates, improving component rendering performance without sacrificing readability.
## 2024-08-20 - Early Returns to Short-Circuit Expensive API Fan-outs
**Learning:** In backend data enrichment pipelines, such as `resolveLiveURLDetailed` checking for `CNAME` files concurrently across multiple paths, making exhaustive requests when the answer is already available locally wastes API rate limits and adds significant latency (especially when the requests result in 404s).
**Action:** Always check local or immediately available structured data (like `repo.Homepage`) before initiating expensive concurrent API fan-outs. Implement early returns to short-circuit processing when the required data can be resolved cheaply.
## 2024-08-28 - Intl.DateTimeFormat Instantiation Overhead in React
**Learning:** Instantiating `Intl.DateTimeFormat` or calling `Date.prototype.toLocaleDateString` directly inside a heavily invoked callback (like formatting a label for hundreds of items rendered dynamically on interaction or in an array map) incurs significant performance penalties due to expensive parser/formatter setup overhead in JS engines.
**Action:** When repeatedly formatting dates using native APIs across many items, always instantiate the `Intl.DateTimeFormat` object once outside the component or loop, and reuse its `.format()` method to dramatically reduce compute overhead.
## 2024-09-04 - Memoizing Hover State Re-renders with Complex Formatting
**Learning:** In React components rendering large arrays (like a contribution heatmap with 210+ cells), handling hover state interactions using standard local state (`useState`) triggers a full re-render of the entire component. If the render loop involves iterating over the large collection and performing expensive operations like `new Date()` instantiation and `Intl.DateTimeFormat.format()` on each item, a simple mouse hover event will block the main thread and cause a significant lag in responsiveness.
**Action:** Always extract and pre-calculate expensive operations, like iterating and formatting elements in large arrays, using a `useMemo` hook based on the actual source data dependencies. By pre-formatting the data into a static mapped shape, hover-triggered re-renders become incredibly cheap because the layout and logic remain unchanged without executing any redundant formatting.
## 2024-09-04 - Redundant Date Instantiations in Render Loops
**Learning:** In React components rendering large arrays without `useMemo`, calling functions that instantiate `Date` objects repeatedly inside mapping functions, especially duplicating identical instantiations (e.g. `Date.now()` or `new Date(isoDate)` multiple times), severely degrades performance during render cycles due to parsing and allocation overhead.
**Action:** When a mapped formatting function requires current context (like `Date.now()` or `new Date().getFullYear()`), hoist these values outside the mapping loop. Additionally, wrap the array mapping in a `useMemo` block to memoize the rendered output, preventing O(n) re-calculations on potential future component updates.
## 2024-10-25 - Caching SHA256 hashes of static API keys
**Learning:** In Go backend applications, validating a static API key on every request (e.g. `forceRefresh`) by performing a constant-time comparison against a hash requires hashing both the provided key and the expected internal key on every invocation. Re-hashing the expected internal key (`sha256.Sum256([]byte(h.internalAPIKey))`) on each request is redundant CPU overhead.
**Action:** When validating static secrets using hashed constant-time comparisons, pre-calculate the hash of the expected secret once during service/handler initialization (e.g. in `NewHandler`) and store it (`internalAPIKeyHash [32]byte`). At request time, hash only the provided key and compare it directly against the pre-calculated hash. Ensure the constant-time comparison is executed unconditionally before any early-return checks (like checking if the internal key is empty) to avoid introducing timing side channels.
## 2024-10-26 - Payload Minimization in Concurrent API Fan-outs
**Learning:** When performing concurrent API fan-outs to fetch a specific data point (like the latest release tag for multiple repositories), using an endpoint or query parameter that returns full histories (e.g., `/releases?per_page=20` which includes large Markdown bodies) significantly bloats JSON payloads, causing unnecessary memory allocation, parsing overhead, and network transfer time.
**Action:** Always constrain API queries to return only the necessary data. For fetching the latest item, implement specific methods (like `GetLatestReleases`) using strict limits (e.g., `?per_page=1` or `/latest` endpoints) to minimize the payload size and speed up concurrent processing pipelines.
